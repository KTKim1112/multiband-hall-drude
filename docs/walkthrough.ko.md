# 처음부터 끝까지 — 이 프로그램을 쓰는 법

헌법 제VIII조가 `docs/` 아래 교육자료를 한국어로 쓰는 것을 허용합니다.
이 문서는 **명세가 아니라 안내**입니다. 규칙은 `docs/spec.ko.md` 에 있습니다.

## 1. 5분 안에 돌려 보기

```bash
python -m pip install -r requirements.txt
python -m mbfit --data tests/data/synthetic_5K.csv --config configs/synthetic_5K.json --out results
```

`results/` 안에 파일 열 몇 개가 생깁니다. **`diagnostics.csv` 를 먼저 여십시오.**
파라미터보다 먼저입니다.

## 2. 왜 진단을 먼저 보라고 하는가

이 프로젝트가 존재하는 이유가 여기에 있습니다. 합성 데이터로 측정한 결과입니다
(`docs/research.ko.md` §4.3):

| | 값 |
| --- | --- |
| R²(종방향) | 0.99959 |
| R²(Hall) | 0.99999 |
| **저이동도 carrier 의 밀도 오차** | **35 %** |

곡선은 완벽하게 맞고, 숫자는 3분의 1이 틀렸습니다. **fit 품질은 파라미터
정확도의 증거가 아닙니다.** R² 만 보면 알 방법이 없습니다.

그래서 `diagnostics.csv` 에는 "답을 믿지 말아야 할 근거"가 들어갑니다.
그중 **가장 먼저 볼 것은 `D_ILL_CONDITIONED`** 입니다.

### 진단 읽는 순서

| 코드 | 무슨 뜻인가 | 무엇을 해야 하나 |
| --- | --- | --- |
| `D_ILL_CONDITIONED` | **데이터가 파라미터 조합 하나 이상을 결정하지 못함** | carrier 를 줄이거나, 자기장 범위를 넓히거나, 결론을 유보 |
| `D_LOW_MU_B` | 이 carrier 는 `mu*B < 1` 이라 개별 분해가 안 됨 | 그 carrier 값은 인용하지 말 것. 숫자를 보고 판단 (0.96 과 0.08 은 다름) |
| `D_NON_UNIQUE` | 같은 품질의 서로 다른 해가 존재 | 초기값을 바꿔 가며 재확인 |
| `D_RESIDUAL_STRUCTURE` | 잔차가 잡음이 아니라 구조 | **모델이 부족함.** band 추가나 다른 물리를 의심 |
| `D_AT_BOUND` | 파라미터가 bound 에 붙음 | bound 를 넓혀 보고 결과가 바뀌는지 확인 |
| `D_JUMP` + `D_LABEL_SWAP` | 온도 사이 도약 | **둘을 함께 보십시오.** swap 이면 물리적 변화가 아님 |
| `D_PRIORS_ACTIVE` | 이 prior 가 결과를 함께 빚었음 | `--no-priors` 로 다시 돌려 비교 |
| `D_BOUND_OVERRIDE` | 특정 온도의 bound 를 손댔음 | 가장 위험한 설정. 근거를 적어 둘 것 |

숫자 예시로, §1 의 명령(합성 fixture 5 K)을 그대로 돌리면 이렇게 나옵니다.

```
D_RESIDUAL_STRUCTURE  rhoxx  측정 -18.2  임계 -3.0  근거 AC-007
D_RESIDUAL_STRUCTURE  rhoxy  측정 -10.0  임계 -3.0  근거 AC-007
D_LOW_MU_B            e_slow 측정 0.921  임계 1.0   근거 research 4.3
```

읽는 법: **파라미터는 잘 결정되었지만**(`D_ILL_CONDITIONED` 없음,
`D_NON_UNIQUE` 없음) **4-carrier Drude 모델이 이 데이터를 완전히 표현하지는
못한다**(잔차가 계통적). 그리고 가장 느린 electron 은 임계 바로 아래입니다.

## 3. 권장 작업 순서

`docs/quickstart.ko.md` 의 표를 풀어 쓰면 이렇습니다.

### A. 아무것도 부과하지 않고 시작

carrier 와 columns 만 선언합니다. **모든 기본값이 아무것도 하지 않도록**
골라져 있으므로, 이것만으로 stage A 가 됩니다.

```json
{
  "schema_version": "1.0",
  "columns": {"T": "T(K)", "B": "B(T)",
              "rhoxx": "rhoxx(microohm cm)", "rhoxy": "rhoxy(microohm cm)"},
  "carriers": [
    {"name": "h1", "kind": "hole",
     "density": {"init": 5e20, "min": 1e17, "max": 1e23},
     "mobility": {"init": 15000, "min": 1, "max": 1e6}}
  ]
}
```

여기서 나오는 결과가 **이후 모든 것을 비교할 기준선**입니다. 여기서 파라미터가
튄다면, 그것은 데이터가 요구한 것입니다.

### B. 온도를 이어 본다

```json
"optimization": {"temperature_strategy": "sequential"}
```

**sequential 은 smoothing 을 하지 않습니다.** 탐색이 시작하는 자리를 바꿀 뿐
최소화 대상을 바꾸지 않습니다. 해가 온도를 따라 이어지는지 보는 용도입니다.

### C. Production fit — **온도가 4~5개 이상일 때만**

```json
"optimization": {"temperature_strategy": "global_smooth"},
"smoothing": {"enabled": true, "order": 2,
              "lambda_density": 0.01, "lambda_mobility": 0.01}
```

**결합 penalty 가 작동하는 유일한 모드**입니다. `order: 2` 를 쓰십시오.
1차는 추세 자체를 눌러 버리고, 2차는 추세를 통과시키면서 고립된 이탈만
억제합니다 (측정 결과는 `docs/research.ko.md` §5.5).

> **이 단계를 건너뛰어야 하는 경우가 있습니다.** 2차 penalty 는 연속한 온도
> 3개마다 곡률 하나를 만듭니다. 온도가 3개뿐이면 내부 마디가 **하나**이고,
> penalty 는 가운데 온도를 양 끝을 잇는 직선 위로 밀어붙이는 것 이상을 하지
> 못합니다. 시료의 5, 20, 40 K 데이터에서 실제로 측정했고 그 표는 research §5.6
> 에 있습니다. 시료에서 잰 것이라 프로그램과 함께 공개되지 않지만, 결론은
> 이렇습니다: `lambda` 를 의미 있는 크기까지 올리면 **잘 결정된 5 K 쪽이 크게
> 움직이고, 구해 주려던 40 K 는 `R2` 가 오히려 나빠집니다.**
> 계열이 짧으면 **B 단계에서 멈추고 독립 fit 을 보고하십시오.**

`lambda` 는 `0.01` 부터 올리고, **조건수가 좋은 온도들이 5 % 넘게 움직이기
시작하면 거기서 멈추십시오.** 그 지점을 넘으면 penalty 가 데이터에게 배우는
것이 아니라 데이터에게 지시하는 것입니다.

상전이가 범위 안에 있으면 반드시 끊으십시오:

```json
"smoothing": {"breaks_K": [94.0]}
```

**단, 끊을 자리는 상전이지 Hall 부호 전환이 아닙니다.** 부호 전환은 carrier
들의 `sigma_xy` 기여가 상쇄되는 지점일 뿐, 완벽히 매끄럽게 변하는 carrier
집합도 지나가면서 하는 일입니다. 그리고 실무적으로, 구간 하나에 온도가 3개보다
적게 남도록 끊으면 그 구간의 2차 penalty 는 **조용히 사라집니다** (온도 3개에
break 하나를 두면 penalty 행이 8개에서 0개가 됩니다).

### D. 무엇이 설정이었는지 확인 — 생략 불가

```bash
python -m mbfit --data d.csv --config c.json --out results_nopriors --no-priors
```

soft prior 를 전부 끄고 한 번 더 돌립니다. **두 실행 사이에서 carrier 밀도가
유의미하게 움직인다면, 그 차이는 데이터가 아니라 prior 가 말하고 있는
것입니다.** 헌법 제X조가 모든 제약에 대해 요구하는 확인입니다.

## 4. 오차막대 읽는 법 — 이것이 덮는 것과 덮지 않는 것

`uncertainty.enabled` 를 켜면 파일 세 개가 더 나옵니다. 켜는 법:

```json
"uncertainty": {"enabled": true, "resamples": 200, "block_length": 20}
```

| 파일 | 무엇인가 |
| --- | --- |
| `uncertainty_<T>K.csv` | 파라미터마다 값·구간·1시그마 |
| `correlation_<T>K.csv` | 파라미터끼리 무엇이 함께 움직이는가 |
| `derived_vs_T.csv` | **총 hole·총 electron·그 비·그 차**, 각각 구간과 함께 |

### 먼저 볼 것은 `derived_vs_T.csv` 입니다

파라미터 8개에 오차막대 8개를 보면 **정작 인용할 숫자가 그중에 없다**는 사실이
가려집니다. 시료의 5 K sweep 에서 잰 1시그마는 research 에 표로 있고 — 시료에서
잰 것이라 여기 옮기지 않습니다 — 그 표가 말하는 순서는 이렇습니다.

| 양 | 얼마나 결정되는가 |
| --- | --- |
| 개별 carrier 의 밀도 하나 | 가장 나쁨 |
| **총 hole, 그리고 hole / electron 비** | **개별 carrier 보다 몇 배 좋음** |
| **보상 (총 hole − 총 electron)** | **가장 나쁨. 큰 두 수의 차이라 상대오차가 커짐** |

**총합은 개별 carrier 보다 훨씬 잘 결정되고, 그 차는 훨씬 나쁘게 결정됩니다.**
그래서 인용할 결론은 "hole 과잉 몇 퍼센트" 하나가 아니라

> **hole 과잉 (값), 1시그마 (구간)**

의 꼴이어야 합니다. 그래야 0 에서 몇 시그마 떨어져 있는지 말할 수 있고, 보상
상태가 아니라는 주장을 **정량적으로** 할 수 있습니다.

### `D_INTERVAL_LOWER_BOUND` 가 뜨면 — 거의 항상 뜹니다

이 진단은 **그 온도의 잔차가 구조적일 때** 나옵니다. 뜻은 이렇습니다.

> 구간은 **"같은 측정을 다시 했을 때 잔차가 다르게 떨어지면"** 을 덮습니다.
> 애초에 잔차를 구조적으로 만든 **모델 부족은 덮지 않습니다.**

왜 못 덮는지는 간단합니다. 수렴한 fit 은 Jacobian 에 직교하는 잔차를 남깁니다.
즉 **그 fit 이 안고 있는 잔차는 그 fit 을 움직일 수 없는 유일한 교란**입니다.
재샘플링해도 *다른* 모양의 같은 크기 오차가 무엇을 했을지는 복원되지 않습니다.

실제 크기: 기준 데이터에서 이 구간은 **약 3배 과소진술**합니다
(`docs/002-research.ko.md` §3.2). 그러므로

- **논문에 쓸 때**: 구간을 그대로 쓰되 "resampling 기반이며 모델 부족은 포함하지
  않는다"를 명시하십시오. `docs/002-research.ko.md` §4.8 의 반사실 추정(5~15 %)이
  모델 부족까지 포함한 값입니다.
- **비교에 쓸 때**: 같은 모델로 얻은 두 결과를 비교하는 것은 괜찮습니다. 모델
  부족이 양쪽에 공통이기 때문입니다.

### `block_length` 는 선언이지 발견이 아닙니다

잔차의 상관 길이만큼 잡아야 합니다. 기준 데이터에서 block 길이를 1 에서 240 까지
바꾸면 **구간이 5배 벌어집니다.** 원리적으로 정해 주는 논거가 없습니다.

- 잔차가 **구조적**이면 (runs test 가 크게 음수) `20` 근처
- 잔차가 **진짜 잡음**이면 `1`

어느 쪽을 썼는지가 `uncertainty_<T>K.csv` 와 `resolved_config.json` 에 함께
기록되니, 독자가 무엇이 가정되었는지 볼 수 있습니다.

`resamples` 는 **아끼지 마십시오.** 40 회로 줄이면 16·84 백분위가 안쪽으로
편향되어 구간이 5 % 좁아집니다. 기본값 200 을 쓰십시오.

### `correlation_<T>K.csv` 가 말해 주는 것

기준 데이터에서 가장 강한 쌍은 **빠른 hole 밀도와 빠른 electron 밀도, `+0.9`**
입니다. 함께 움직인다는 뜻이고, 그래서 **둘의 합은 잘 결정되고 각각은 아닙니다.**
어떤 파라미터를 개별적으로 인용해도 되는지 여기서 판단하십시오. 상관계수가
`±0.9` 를 넘는 쌍은 **따로 인용하면 안 됩니다.**

### 채널이 정말 밴드인가 — `harmonics_vs_T.csv`

비원형 Fermi 면 궤도 **하나**가 `mu, mu/2, mu/3 …` 의 여러 채널처럼 보일 수
있습니다. 이 파일이 세 조건을 따로 보고합니다: 정수비, 감소하는 가중치, 단일 부호.
셋이 모두 성립하면 `D_HARMONIC_LADDER` 가 뜨고, **밴드가 여럿이라고 말할 수
없습니다.**

기준 데이터는 세 온도 모두 `single_sign` 에서 깨집니다 — electron 과 hole 이 둘 다
있고, 궤도 하나의 조화는 전하 부호를 바꿀 수 없습니다. **진짜 다밴드라는 증거**이고,
Methods 에 그대로 쓸 수 있습니다.

### 접점은 괜찮았나 — `D_PARITY_VIOLATION`

대칭화 **전에** 잰 값입니다. 전압 접점이 정확히 마주 보지 않으면 종방향 신호가
Hall 채널에 섞이고, 그것은 자기장 부호를 따라 뒤집히지 않습니다. 대칭화가
제거하지만 **얼마나 제거했는지가 시료와 접점에 대한 유일한 증거**입니다. 몇 퍼센트는
흔하고, 크면 접점 기하나 시료 균질성을 의심하십시오.

한쪽 극성만 측정했다면 `D_SINGLE_POLARITY` 가 뜹니다. **혼입이 0 이라는 뜻이 아니라
측정할 수 없었다는 뜻**이고, 대칭화도 불가능합니다.

## 5. 이동도 스펙트럼 — carrier 가 몇 개인가

```json
"spectrum": {"enabled": true, "lorentzian_terms": 6}
```

온도마다 파일 네 개가 나옵니다. **`spectrum_stability_<T>K.csv` 를 먼저
여십시오.** `spectrum_peaks_<T>K.csv` 가 아닙니다. 봉우리 개수보다 그 개수가
얼마나 단단한지가 먼저입니다.

### 이 기능은 무엇을 하는가 — 다섯 단계

feature 001 은 선생님이 **선언한** 개수의 carrier 를 맞춥니다. 이 기능은 그
개수가 옳았는지를 묻습니다.

```text
1. 정규화   X = sigma_xx/sigma_xx(0),  Y = sigma_xy/sigma_xx(0)
2. 확장     Lorentzian n 개를 X 와 Y 에 동시에 맞춘다 (이동도 집합 공유)
3. 변환     Kramers-Kronig 변환. 닫힌 형태라 수치적분이 없다
4. 분리     hole 몫과 electron 몫으로 가른다
5. 역문제   부호마다 따로 이동도 스펙트럼을 푼다
```

**3~4 단계가 이 기능의 핵심입니다.** 예전 판은 이 두 단계를 건너뛰고 측정값을
곧바로 역산했는데, 봉우리 개수가 정규화 세기에 따라 6개에서 2개 사이를 움직여
어떤 개수도 인용할 수 없었습니다. 원인은 hole 과 electron 의 기여가 Hall
채널에서 **부분적으로 상쇄**되기 때문입니다. 합만 보는 역문제는 서로 다른 여러
분할 사이에서 고를 수가 없습니다.

먼저 분리하면 그 자유도가 사라집니다. 알려진 4-carrier 합성 데이터에서
측정하면, 분리 후에는 hole 쪽이 `2001`, `29552` 를, electron 쪽이 `902`,
`25011` 을 **정규화 11 decade 전체에서 똑같이** 돌려줍니다(참값 2000, 30000,
900, 25000). 예전 판이 흔들리던 바로 그 범위입니다.

### `lorentzian_terms` — 반드시 선생님이 정해야 하는 값

2단계의 차수 `n` 입니다. 프로그램이 스스로 정하지 않습니다.

**서로 다른 이동도의 개수보다 낮게 주면 안 됩니다.** 참 carrier 6개에서
측정한 결과, `n = 5` 는 최악의 이동도가 `+633 %` 어긋났고 `n = 6` 은 6개 중
4개가 `2 %` 이내였습니다. 낮은 차수는 데이터를 표현할 수 없고, 그 뒤의 모든
단계가 그 실패를 물려받습니다.

**높은 쪽으로 틀리십시오.** 제약된 매개변수화에서 `n` 항의 확장은 그 자체로
`2n`-carrier Drude 모형이므로, 과하게 선언하는 데 드는 비용이 없습니다.
`lorentzian_terms` 를 예상 이동도 개수 이상으로 두는 것이 기본 지침입니다.

차수가 모자라면 `D_SPECTRUM_EXTENSION_UNDERFIT` 가 뜹니다. 그러면 올리십시오.

### 답을 아는 데이터에서는 작동합니다

carrier 6개(hole 45000/12000/1500, electron 33000/9000/800)로 만든 합성
데이터에서:

| `rho` 의 잡음 | 최악의 이동도 오차 | 최악의 밀도 오차 | 제안 |
| --- | --- | --- | --- |
| 없음 | `1.9 %` | `1.8 %` | `3 + 3` |
| `0.05 %` | `4.1 %` | `3.2 %` | `3 + 3` |

정규화 15 decade 전체에서 부호마다 고원이 하나씩입니다. 그것이 믿을 만한
봉우리 개수의 모습입니다.

### 선생님 데이터에서는 — 역문제는 정해지고, 확장이 정해지지 않습니다

`n = 6`, 출발점 12개로 측정한 결과:

| | 제안 | 고원 | 음수 몫 | 확장 잔차 |
| --- | --- | --- | --- | --- |
| 5 K | `3 + 3` | 부호마다 하나, 15 decade 전체 | 없음 | `5.2e-2` |
| 20 K | `3 + 3` | 부호마다 하나, 15 decade 전체 | 없음 | `4.2e-2` |
| 40 K | `4 + 5` | 부호마다 하나, 15 decade 전체 | 없음 | `1.1e-1` |

**예전 판과 달리 고원이 하나씩입니다.** 5 단계의 역문제는 더 이상 모호하지
않습니다. 그런데 아직 개수를 못 박을 수 없고, 이유가 바뀌었습니다.

**확장 잔차를 보십시오.** 정규화된 채널의 측정 잡음은 `7e-5` 인데 확장 잔차는
`5.2e-2`, 그 700배입니다. 항을 더해도 나아지지 않습니다:

| 항 개수 | 확장 잔차 | 제안 |
| --- | --- | --- |
| 4 | `7.3e-2` | `3 + 3` |
| 6 | `5.2e-2` | `3 + 3` |
| 8 | `4.7e-2` | `3 + 4` |
| 10 | `4.7e-2` | `3 + 4` |

`4.7 %` 에서 평평해집니다. `n` 항의 제약된 확장이 `2n`-carrier Drude 모형이므로,
**어느 차수에서도 `4.7 %` 아래로 내려가지 않는다는 것은 이 측정이 어떤 크기의
Drude 모형으로도 표현되지 않는 구조를 담고 있다는 뜻입니다.** research 001 §4.8
이 `3 %` 의 모형 오설정으로 측정한 것과 같은 이야기이고, 이쪽이 더 강합니다.
"carrier 를 몇 개 더 넣으면 되지 않나"는 이것으로 닫힙니다. 두 개를 더 넣어도
아니고 스무 개를 더 넣어도 아닙니다.

그리고 제안이 `n` 과 함께 움직입니다(`3+3` → `3+4`). 확장이 Lorentzian 이 아닌
구조를 맞추고 있고, 남는 자유도를 어디에 놓을지가 물리로 결정되지 않기
때문입니다. **그래서 개수는 여전히 선생님이 정합니다.** 프로그램은 제안하고,
그 제안을 제한하는 근거를 함께 냅니다.

### 진단 여덟 개를 읽는 법

두 무리입니다. 앞의 넷은 2단계의 확장이 무엇을 했는지, 뒤의 넷은 5단계의
역문제가 무엇을 결정할 수 있었는지를 말합니다. 뒤의 넷은 **부호마다 따로**
나옵니다. 분리한 뒤에는 hole 문제와 electron 문제가 독립적으로 성공하고
실패하기 때문입니다.

| 코드 | 뜻하는 것 | 어떻게 하나 |
| --- | --- | --- |
| `D_SPECTRUM_EXTENSION_UNDERFIT` | 확장이 데이터를 못 따라감 | `lorentzian_terms` 를 올리십시오. 올려도 안 되면 §6.1 의 `4.7 %` 바닥입니다 |
| `D_SPECTRUM_EXTENSION_SATURATED` | 항이 이동도 범위 끝에 앉음 | `mu_min_cm2Vs` / `mu_max_cm2Vs` 를 넓히십시오 |
| `D_SPECTRUM_EXTENSION_MULTIMODAL` | 출발점 절반 미만이 일치 | 참고용 메모입니다. `lorentzian_multi_start` 를 늘려 보되, 답이 그대로면 그대로 쓰십시오 |
| `D_SPECTRUM_UNCONSTRAINED` | 비음수 제약을 끔 | 논문 방식 재현이 목적이 아니면 다시 켜십시오 |
| `D_SPECTRUM_NEGATIVE_PART` | 분리된 전도도가 부호를 잃음 | 제약을 껐을 때만 납니다. 다시 켜십시오 |
| `D_SPECTRUM_NOISE_UNREACHED` | 어느 세기도 선언된 잡음까지 못 감 | 스펙트럼의 모양을 만든 것은 잡음이 아니라 모델이 놓친 것입니다. 개수를 인용하지 마십시오 |
| `D_SPECTRUM_UNRESOLVED` | 고원이 아예 없음 | 이 데이터는 이 부호에 대해 아무 개수도 지지하지 않습니다 |
| `D_SPECTRUM_AMBIGUOUS` | 고원이 둘 이상 | 둘 이상의 개수가 맞습니다. 고르지 마십시오 |

어느 것도 "스펙트럼이 틀렸다"가 아닙니다. **어디까지 인용해도 되는가**를
말합니다.

### `noise_source` — 여전히 생각해야 하는 설정

`"residual"` 이면 fit 잔차의 2차 차분에서 잡음을 추정하고, 숫자 쌍이면 채널마다
직접 선언합니다. 불일치 원리가 무엇을 견주는지를 정하는 값이라, 잘못 고르면 그
뒤의 어떤 단계도 되돌릴 수 없습니다.

한 가지 더. 정규화 때문에 `Y` 가 작아서 — 5 K 에서 `max|Y|` 가 `0.09` 정도 —
세로 채널의 절대 오차가 `Y` 에서는 큰 상대 오차가 됩니다. 측정하면 `rho` 의
`0.05 %` 잡음이 `Y` 에서 `3.5 %` 가 됩니다. **72배입니다.** 이 방법은 직접
fit 보다 세로 방향 잡음에 훨씬 민감하고, 그것은 구현이 아니라 정규화 자체의
성질입니다.

### 절대 하지 말아야 할 것: 두 판별법 합성

`harmonics_vs_T.csv` 의 사다리 검정을 **스펙트럼 봉우리에 적용하지 마십시오.**

`12000` cm^2/Vs 궤도 하나를 사이클로트론 조화 4개로 펼쳐 측정한 결과:

| | 비율 | 사다리 판정 |
| --- | --- | --- |
| 생성된 그대로의 조화 | `1.00`, `2.00`, `3.00`, `4.00` | **사다리다** |
| 스펙트럼이 돌려준 봉우리 | `1.00`, `2.10`, `3.68` | **아니다** |

스펙트럼이 약한 조화 둘을 합치고 남은 것을 옮겨 놓으면, 사다리 검정이 그것을
통과시킵니다. 스펙트럼을 먼저 돌리고 판별을 나중에 돌리면 **궤도 하나가 진짜
multiband 라는 무죄 판결**을 받습니다.

어느 판별도 틀리지 않았습니다. **둘을 합성하는 것이 틀렸습니다.** 사다리 검정은
fit 이 돌려준 carrier 에만 적용하십시오. 프로그램이 그렇게 하고 있고, FR-078 이
그것을 요구사항으로 못박았습니다.

### 가장 먼저 볼 파일이 바뀌었습니다 — `spectrum_roundtrip_<T>K.csv`

스펙트럼이 읽어낸 carrier 를 **다시 Drude 모형에 넣어** 측정과 비교한 값이
채널마다 한 줄씩 들어 있습니다. 이것이 스펙트럼의 검사 중 유일하게 결과를
**측정**과 견주는 것입니다. 나머지는 전부 방법이 자기 자신을 검사합니다.

| `rhoxy` 왕복 오차 | 뜻 |
| --- | --- |
| `5 %` 이하 | 스펙트럼의 `(n, mu)` 를 초기값으로 써도 좋습니다 |
| `5 %` 초과 | `D_SPECTRUM_ROUNDTRIP`. **그 값들을 밀도·이동도로 인용하지 마십시오** |

`rhoxx` 는 작은데 `rhoxy` 만 큰 것이 보통이고, 그건 결함이 아니라 구조입니다.
봉우리의 밀도가 `sigma_xx(0) * S = n q mu` 로 **세로 채널에서만** 나오므로
Hall 채널을 붙드는 것이 없습니다.

**이 값이 클 때 무엇을 뜻하나.** 흔한 원인은 carrier 가 이동도 **하나**가 아니라
이동도 **분포**를 갖는 것입니다. 봉우리를 그 중심의 carrier 하나로 읽으면
1차 모멘트 `n mu` 는 지키고 2차 모멘트 `n mu^2` 는 잃는데, `rho_xy` 를 정하는
것이 2차 모멘트입니다. research 003 §8.3 이, 각 carrier 에 로그 폭 `0.15` 의
퍼짐을 준 합성 데이터에서 확장 잔차는 `9.8e-5` 로 훌륭한데 왕복 `rho_xy` 는
`39.6 %` 인 것을 측정했습니다.

**확장 잔차가 작다고 안심하지 마십시오.** 그 둘은 다른 질문입니다. 확장 잔차는
"데이터가 Lorentzian 으로 써지는가", 왕복은 "거기서 읽어낸 봉우리가 그렇게
되는가" 입니다. 독자가 가진 질문은 두 번째뿐입니다.

### 개수만 받지 말고 이동도 창까지 받으십시오

스펙트럼을 **출발점으로만** 쓰면 큰 모형이 정해지지 않습니다. 제안된 6개를
초기값으로 넣고 40번 돌리면 40개의 다른 답이 나옵니다(파라미터가 최대
`7750 %` 차이).

이동도를 **봉우리 근방으로 묶으면** 달라집니다. 시료의 20 K sweep 에서 각
이동도를 `봉우리/3` ~ `봉우리*3` 으로 제한하니 퍼짐이 여섯 자릿수 넘게
떨어졌고, 어떤 carrier 도 경계에 닿지 않았으며, 4-carrier 대비 잔차 이점이
살아남았습니다. 숫자는 research 에 있습니다.

설정 예 — 봉우리가 `50000` 에 있을 때:

```json
"carriers": [
  {"name": "h1", "kind": "hole",
   "density":  {"init": 5.0e19, "min": 1e15, "max": 1e23},
   "mobility": {"init": 50000, "min": 16667, "max": 150000}}
]
```

`min` 과 `max` 를 봉우리의 1/3 과 3배로 둔 것입니다.

**다만 조이는 데에 한계가 있습니다.** `D_AT_BOUND` 가 뜨면 데이터가 아니라
창이 이동도를 고른 것입니다. 퍼짐이 사라질 때까지 계속 조이면 fit 을 그만두고
강요를 시작한 것이므로, 거기서 멈추고 더 작은 모형으로 돌아가십시오.

그리고 **퍼짐과 조건수는 다릅니다.** 경계를 묶으면 퍼짐(탐색의 재현성)은
고쳐지지만 조건수(데이터가 답을 결정하는가)는 거의 그대로입니다. 20 K 에서
묶든 안 묶든 `1.3e4` 입니다. 그러니 `D_ILL_CONDITIONED` 는 그대로 서 있고,
인용할 오차막대는 여전히 `uncertainty.enabled` 의 재샘플링에서 와야 합니다.

### 그래서 스펙트럼을 언제 쓰나

- **개수를 정하려고 쓰지 마십시오.** 제안을 받아서 선생님이 정하는 것입니다.
  프로그램은 선언된 carrier 를 결코 덮어쓰지 않습니다.
- **`spectrum_extension_<T>K.csv` 를 꼭 함께 보십시오.** 모든 봉우리는 확장이
  고른 이동도 위에 앉습니다. 확장이 허용하지 않은 구조는 스펙트럼도 찾아내지
  못합니다.
- **쓸모 1 — 이동도 축의 어디에 전도도가 있는지** 보는 것. 선언한 carrier 가
  스펙트럼과 모순되지 않는지 확인할 수 있습니다.
- **쓸모 2 — fit 의 초기값과 이동도 창.** `spectrum_peaks_<T>K.csv` 의
  `(n_i, mu_i)` 를 초기값으로 쓰고, `min`/`max` 를 그 봉우리의 1/3 ~ 3배로
  두십시오. 초기값만으로는 큰 모형이 정해지지 않고, 창까지 주면 정해질 수
  있습니다(바로 위 절).
- **쓸모 3 — 모형이 부족한지 진단.** 확장 잔차가 차수를 올려도 내려가지
  않으면, 문제는 carrier 개수가 아닙니다.

### 봉우리는 밴드가 아닙니다

스펙트럼을 낼 때마다 프로그램이 함께 내는 문장입니다. 봉우리는 **전도
채널**이지 Fermi surface 의 밴드가 아닙니다. 위에서 보았듯 궤도 하나가 봉우리
3개로 읽힐 수 있으므로, 봉우리 개수는 밴드 개수의 **상한**이지 추정값이
아닙니다.

## 5.5 carrier 개수를 무엇이 정하게 할 것인가

절차는 하나입니다. 스펙트럼으로 범위를 잡고, multiband fit 으로 값을 냅니다.
고를 것은 **carrier 개수를 누가 정하느냐** 하나입니다.

```bash
python -m mbfit --data ... --config ... --out ... --count data     # 기본
python -m mbfit --data ... --config ... --out ... --count peaks    # Liu et al. 방식
```

| | `data` (기본) | `peaks` |
| --- | --- | --- |
| 개수 | 봉우리 수는 **상한**. 그 이하 조합을 모두 fit 하고 게이트로 고름 | 봉우리 수로 **고정** |
| 값 | 고른 조합의 fit | 봉우리 값에서 시작한 fit, 스펙트럼에 되먹여 수렴까지 반복 |
| 말할 수 있는 것 | 이 sweep 을 설명하는 데 필요한 전도 채널 수의 **하한**과 그 유효 n·μ | 봉우리 찾기가 고른 개수에서의 fit |
| 쓸 때 | 자기수송 데이터만으로 판단할 때 | 양자진동 등 자기수송 밖의 근거가 개수를 뒷받침할 때 |

### 시료의 데이터에서 잰 결과

5 K 에서 논문 방식의 첫 fit(봉우리 3h+3e 에서 시작)과 data 규칙을 나란히 재
봤습니다. 두 방법의 `R²` 는 세로 채널도 Hall 채널도 **소수점 아래까지 같았고**,
조건수만 일곱 자릿수 넘게 벌어졌습니다. 표는 research 004 §4.2 에 있습니다.

**곡선은 똑같이 맞습니다. 다른 것은 숫자를 믿을 수 있느냐입니다.** 3h+3e 는
carrier 사이에 n 과 μ 를 맞바꿔도 곡선이 거의 변하지 않아, 출발점마다 다른
답이 나옵니다. 12개 온도 전체와 반복 루프까지 돈 결과는 research 004 §4.2 에
있습니다.

### 자기수송이 말할 수 없는 것

- **Fermi pocket 의 수.** 스펙트럼 봉우리 수는 sweep 이 구분하는 채널 수의
  상한이지 밴드 수가 아닙니다. 원형이 아닌 궤도 하나가 봉우리 셋으로 나오는
  것을 합성 데이터로 쟀습니다 (research 003 §7).
- **data 규칙의 carrier 가 실제 pocket 하나라는 것.** 여러 pocket 이 합쳐진 유효
  채널일 수 있습니다. 개수는 하한이고, n·μ 는 그 채널의 유효값입니다.
- 그래서 **pocket 수를 따로 아는 경우**에는 `--count peaks` 나 `fixed_counts`
  (§5.7) 로 개수를 고정하십시오. 그때도 등급과 통과 못 한 시험을 함께 보십시오.

### 봉우리를 그대로 답으로 쓰던 모드는 왜 없어졌나

이전 판에는 스펙트럼 봉우리를 carrier 로 읽은 것을 곧바로 답으로 삼는
"spectrum 모드" 가 있었습니다. 논문 보충자료를 다시 읽어 보니 논문의 최종 값은
fit (2DMAT) 에서 나오고, 봉우리 값은 그 fit 의 출발점이었습니다. 그 모드는
논문의 절차가 아니었고, 잰 결과도 R² 가 모든 온도에서 낮았기 때문에 뺐습니다.

## 5.6 등급 A·B·C·D 를 읽는 법

data 규칙은 고른 조합에 등급을 답니다. 등급은 **조건수**로 매겨지고, 게이트가
아니라 **얼마나 믿을지**를 말합니다.

| 등급 | 조건수 | 뜻 | 인용할 때 |
| --- | --- | --- | --- |
| **A** | ≤ 10³ | 파라미터가 결정됨 | 자릿수까지 써도 됨 |
| **B** | ≤ 10⁴ | 추세는 되고 자릿수는 안 됨 | **구간을 반드시 함께** |
| **C** | ≤ 10⁶ | 모양만 | 값을 인용하지 말 것 |
| **D** | 그 위 | 결정 안 됨 | 인용 불가 |

임계 `1000` 은 research 001 §4.6 이 두 점으로 보정한 값입니다. 조건수 `4.0e2`
에서는 모든 파라미터가 `0.1 %` 로 돌아왔고, `5.2e3` 에서는 저이동도 밀도가
`35 %` 틀렸습니다. **그 둘을 가르는 값이지 쓸모 있음과 없음을 가르는 값이
아닙니다** — 그래서 게이트가 아니라 등급입니다.

B 등급에서는 조건수보다 **재샘플링 구간이 더 직접적인 양**입니다. 독자가 실제로
인용하는 것이 그것이니까요.

### 통과하는 조합이 없다고 나오면

프로그램이 가장 가까운 조합과 그것이 떨어진 시험을 이름으로 말합니다. 시험은
넷입니다.

| 시험 | 떨어졌다는 뜻 | 할 일 |
| --- | --- | --- |
| `fits` | 데이터를 못 맞춤 | 개수 상한을 올리거나 모형 밖 구조를 의심 |
| `reproducible` | 돌릴 때마다 다른 답 | 이 개수는 데이터가 못 정합니다. 줄이십시오 |
| `earns` | carrier 하나가 전도의 `0.1 %` 미만 | 그 carrier 를 빼십시오 |
| `free` | carrier 가 경계에 붙음 | 이동도 창을 넓히십시오 |

**시험을 완화해서 통과시키지 마십시오.** 프로그램이 그 길을 막아 둔 이유는,
완화해서 얻은 답은 데이터가 아니라 완화가 낸 답이기 때문입니다.

## 5.7 온도에 걸쳐 개수를 고정하기

온도마다 최적 개수를 따로 고르면 **`n(T)` 곡선을 그릴 수 없습니다.** 밑에서
모형이 바뀌면 그건 곡선이 아닙니다.

```json
"workflow": {
  "fixed_counts": {"5": [2, 2], "10": [2, 2], "20": [2, 2], "30": [2, 2],
                   "40": [2, 2], "50": [2, 2], "60": [2, 2], "70": [2, 2],
                   "80": [1, 1], "90": [1, 1], "100": [1, 1], "120": [1, 1]}
}
```

프로그램이 **고정의 대가**(잔차가 얼마나 나빠졌는지)를 함께 보고합니다. 이
프로젝트의 12온도에서는 대가가 작았습니다 — 70 K 하나만 스펙트럼이 준 이동도
창을 벗어났습니다.

## 5.8 구간을 하나의 계열로 묶기 — 거칠기와 그 대가

§5.7 로 개수를 고정하면 `n(T)` 를 그릴 수 있게 됩니다. 그다음 질문은 **그 곡선이
하나의 계열로 읽히는가** 입니다. 온도마다 독립으로 맞추면 이웃한 온도의 답이 서로
아무 관계 없이 튈 수 있고, 그 튐이 물리인지 fit 의 골짜기 선택인지는 곡선만 봐서는
구별되지 않습니다.

프로그램은 그것을 숫자 하나로 잽니다. **거칠기**는 파라미터의 로그가 온도에 따라
얼마나 휘는지이며, FR-027 의 결합 penalty 가 최소화하는 바로 그 양입니다. 화면에
나오는 숫자와 optimizer 가 보는 숫자가 같은 숫자라는 뜻입니다. 온도 간격을 고려하므로
(FR-031) 5 K 간격과 20 K 간격을 그 이유만으로 다르게 판정하지 않습니다.

- 명령줄: 실행이 끝나면 마지막에 그 구간의 거칠기를 인쇄합니다. `report.html` 의
  "3. 온도에 따른 파라미터" 아래에도 같은 숫자가 적힙니다.
- 페이지: 다시 맞추기에서 구간을 고른 뒤 그 구간의 거칠기와, 결합을 걸었을 때의
  거칠기를 나란히 보여 줍니다.

**온도 3개 미만이거나 개수가 다른 구간에서는 잴 수 없습니다.** 곡률은 점 셋이 있어야
정해지고, carrier 개수가 바뀌는 구간은 애초에 하나의 계열이 아닙니다. 그럴 때
프로그램은 0 을 내놓지 않고 "잴 수 없다" 고 말합니다. 재지 못한 것을 0 으로 적으면
가장 매끄러운 계열로 읽히기 때문입니다.

### 결합을 걸 때 — 공짜인 강도는 없습니다

구간을 개수로 고정한 뒤 약하게·보통·강하게 중 하나로 온도 결합을 걸 수 있습니다.
기본은 꺼져 있고, 요청해야 켜집니다. **구간별로** 거는 것이 보통 원하시는 형태입니다.

```json
"workflow": {
  "fixed_counts": {"5-60": [2, 2], "70-150": [2, 2]},
  "smooth_band": [{"range": "5-60", "strength": "normal"},
                  {"range": "70-150", "strength": "weak"}]
}
```

`smooth_band` 은 개수를 고정한 **뒤에** 그 구간에만 결합을 겁니다. 페이지의 6단계가
하는 일과 같은 일이고, 6단계에서 확정하면 이 형태의 문서가 표와 함께 나옵니다 —
그래서 같은 답을 명령줄에서 그대로 재현하실 수 있습니다(FR-107).

온도 전체를 한 덩어리로 묶는 옛 형태도 그대로 있습니다. 구간을 나눌 생각이 없을
때만 쓰십시오.

```json
"optimization": {"temperature_strategy": "global_smooth"},
"smoothing": {"enabled": true, "order": 2,
              "lambda_density": 1e-4, "lambda_mobility": 1e-4, "breaks_K": []}
```

이 프로젝트의 sweep 에서 5–90 K 를 하나의 구간으로 놓고 잰 결과입니다.

| 강도 | λ | 가장 나쁜 온도의 잔차 증가 | 거칠기 감소 |
| --- | --- | --- | --- |
| 약하게 | `1e-5` | `5 %` | `6 %` |
| 강하게 | `1e-3` | `131 %` | `65 %` |

> **§3.C 의 `0.01` 과 여기 `1e-3` 이 다른 이유.** §3.C 의 숫자는 온도 **3개**
> (5·20·40 K) 짜리 계열에서 잰 것입니다. 거기서는 2차 penalty 의 내부 마디가
> 하나뿐이라 penalty 행이 8개밖에 없고, 그만큼 `lambda` 를 크게 줘야 무슨 일이
> 일어납니다. 2h+2e 로 재 보면 온도 3개에서 행이 **8개**, 온도 12개에서 **80개**
> 입니다. 행이 열 배면 같은 `lambda` 가 열 배 세게 작용하고, 그 열 배가 바로
> `0.01` 과 `1e-3` 의 차이입니다 — 위 표대로 `1e-3` 에서 이미 잔차가 두 배를
> 넘습니다. **긴 구간에서는 `0.01` 로 시작하지 마십시오.** 두 경우 모두에서
> 유효한 기준은 숫자가 아니라 §3.C 의 규칙입니다: *조건수가 좋은 온도들이 5 %
> 넘게 움직이기 시작하면 멈춘다.*

**대가가 크다는 것은 그 구간에서 모형이 바뀐다는 증거입니다.** 같은 데이터에서
5–60 K 의 거칠기는 `0.431` 이었고 40–90 K 는 `1.186` 이었습니다. 아래쪽은 이미
매끄러워서 결합이 지울 것이 별로 없고, 위쪽은 **이유가 있어서** 거칩니다. 거기에
강한 결합을 걸면 그 이유가 지워집니다. 그러니 대가가 클 때 할 일은 더 세게 누르는
것이 아니라 **구간을 나누는 것**입니다 — `breaks_K` 에 경계를 적거나, 두 구간을 따로
돌리십시오.

거칠기 척도가 개수 분석과 독립으로 같은 60 K 경계를 짚었다는 점은 그 자체로
읽을 만한 결과입니다. 두 가지 서로 다른 방법이 같은 온도를 가리켰다는 뜻이니까요.
다만 그것이 무엇인지 — 전이인지, 새 채널이 열린 것인지, 시료의 사정인지 — 는
자기수송이 답하지 않습니다.

## 5.9 원시 데이터가 대칭이 아닐 때

전압 접점이 정확히 마주 보지 않으면 `ρxx` 에 `ρxy` 가, `ρxy` 에 `ρxx` 가
섞입니다. 프로그램이 그것을 `D_PARITY_VIOLATION` 으로 재서 알려 줍니다.

```bash
python -m mbfit ... --symmetrize-rhoxx --antisymmetrize-rhoxy
```

`ρxx` 를 짝부분 `[r(B)+r(-B)]/2` 로, `ρxy` 를 홀부분 `[r(B)-r(-B)]/2` 로
바꿉니다. `-B` 기록이 없으면 sweep 이 감싸는 경우 **보간**하고, 아니면 그
기록은 그대로 둡니다. 각 경우의 개수가 보고됩니다.

**기본은 꺼져 있습니다.** 프로그램이 묻지 않고 데이터를 바꾸지 않게 하기
위해서입니다. 그리고 켜도 증거는 남습니다 — 패리티 위반은 대칭화 **전에**
측정됩니다.

한쪽 극성만 있는 sweep 에서는 대칭화가 아무 일도 못 합니다. `D_SINGLE_POLARITY`
가 그렇다고 말해 줍니다.

## 6. 자주 부딪히는 것들

### carrier 를 몇 개 넣어야 하나

정답은 없고, 프로그램도 정해 주지 않습니다 (그 기능은 feature 002 로 미뤘고,
이유는 `docs/spec.ko.md` §9 에 적혀 있습니다 — 정보기준은 residual 독립을
가정하는데 이 데이터의 residual 은 강하게 상관되어 있습니다).

실무적으로는: **2개로 시작해 `D_RESIDUAL_STRUCTURE` 가 사라지는지 보고,
늘릴 때마다 `D_ILL_CONDITIONED` 가 켜지는지 보십시오.** 잔차 구조는 남는데
조건수가 나빠지기 시작하면, 그 데이터가 감당할 수 있는 band 수를 넘은 것입니다.

### 왜 내 옛 결과와 electron/hole 이 반대인가

이 프로그램은 **표준 부호 관례(PM-001)** 를 씁니다. 양의 자기장에서 electron 은
`rho_xy < 0`, hole 은 `rho_xy > 0` 입니다. 예전 프로토타입은 반대 관례로
계산했으므로, 그것으로 얻은 결과는 **숫자는 맞고 이름표만 뒤바뀌어**
있습니다. 자세한 것은 `docs/research.ko.md` §2.1 과 §2.4.

측정 배선이 정말로 반대라면 그때는 이렇게 선언합니다:

```json
"model": {"hall_polarity": -1}
```

### 자기장 범위를 자르는 게 좋은가

대개 **아닙니다.** 기준 데이터에서 측정한 결과, `|B| <= 6 T` 로 자르면
파라미터가 최대 21 % 이동하고 6~9 T 예측의 R² 가 0.959 에서 0.757 로
무너졌습니다 (`docs/research.ko.md` C7). 양자진동이 걱정된다면, 자르는 것이
아니라 **잔차로 드러내는 것**이 이 프로그램의 방식입니다.

잘라야 할 이유가 있다면 기능은 있습니다. 다만 제외된 레코드도 **여전히
예측되고 출력되며**, `D_EXCLUDED_MISMATCH` 가 그 대가를 보고합니다.

### 결과를 1년 뒤에 재현하려면

`results/resolved_config.json` 을 그대로 넣으면 됩니다.

```bash
python -m mbfit --data d.csv --config results/resolved_config.json --out check
```

**모든 숫자가 동일해야 합니다.** 그렇지 않다면 결함입니다. 이 파일에는
선언한 값이 아니라 **실제로 작동한 값**이 들어 있으므로, `--no-priors` 로
만든 실행도 스위치 없이 재현됩니다.
